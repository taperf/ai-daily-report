## Aaron Levie — Box CEO

Box CEO Aaron Levie 抛出了一条关于 token 消耗的判断：per-employee 的 token 支出曲线「还看不到天花板」，而且越靠近 AI 的人越确信我们现在仍在采用曲线的早期。他的论证链条是：今年夏秋的模型发布把 state of the art 推进到了「已经很难维持的速度」，结果对大多数生产性用例来说，模型现在才真正开始可用——「编码在 12 个月前基本上还是垃圾，现在终于开始变好了」。而编码一旦跑通，工具调用与 computer use 就随之打开，从前根本没法塞 agent 进去的知识工作领域（金融、生命科学、网络安全）就此变得可行。再往后是新的形态：agent swarm 与后台 agent 会吃掉「我们目前能想象到的任何量级」更多的 token——企业工作流里跑 agent 处理数据、校验工作、做研究、做决策支持。

The diffusion argument matters more than the demand forecast: coding agent is treated as the unlock for computer use, which in turn is treated as the unlock for knowledge work.

> 扩散路径的论证比需求预测更重要：编码 agent 被看作 computer use 的解锁点，而后者又被看作知识工作的解锁点。

## Guillermo Rauch — Vercel CEO

Vercel CEO Guillermo Rauch 给了两条可以直接照抄的方法论。第一条是「拥有你自己的智能路线图」四步：用开放的 SDK 与 harness；用 Gateway 掌握模型选择权；自己拥有 traces 与数据并强制 ZDR（零数据留存）；用私有推理拥有自己的模型。第二条是一个角色转换的观察：过去「用户是人」，你做用户访谈、画用户旅程；现在「用户是 agent」，你跑 eval，而 eval 反过来驱动软件工程循环——他同时贴了 Vercel 内部怎么做 eval 的一篇长文。第三条更宏大：一个软件新纪元——个性化、完全自有、开源，而且质量高于它所取代的东西。

> 那四步路线图是基础设施姿态而非产品宣传：SDK、网关、traces、私有推理，正是锁定真正发生的四个层面。

## Thariq — 前 Anthropic Claude Code 团队成员

## Peter Yang — AI 教程作者

AI 教程作者 Peter Yang 整理了他从设计师 Nate Parrott 那里得到的五条「让 Claude 做设计而不是生成 AI slop」的方法：一，事前把上下文给足——截图、你喜欢的页面、你过去的作品，对既有产品直接让 Claude 用代码重建真实界面；二，研究熟悉的 UX 模式——遇到难布局，让 Claude 找解决同类问题的产品，记下用户已经会用的布局；三，让 Claude 意识到自己的设计偏见——引述原话「模型根本不知道自己的偏见是什么」，在设计文件里明确禁止 serif 字体、米白背景、卡片边缘色条这类「Claude 味」；四，先画线框——在纠结字体和颜色前先把核心用户流程用线框图对齐；五，要多个方案再混编——关键页面一次要 5 个不同字体、颜色、风格的版本，挑出喜欢的部分再让它 remix 出 5 个新版本。

The third point is the one that generalizes: telling a model what its own aesthetic tells are is a prompt-level intervention on taste, not on capability.

> 第三条最有普适性：告诉模型它自己的审美惯性是什么，这是一种作用在品味上、而非能力上的 prompt 干预。

## Dan Shipper — Every CEO

## Latent Space —《[One Million AI Engineer Special] How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco》

视频链接：https://www.youtube.com/@LatentSpacePod

> 说明：feed 提供的链接为频道地址，未能取得单集直链；以下内容严格基于 feed 提供的转写稿，不额外搜索、不补全未提及的信息。

**The Takeaway：** Stanford 的 CS146「现代软件开发者」课程在第二年做了大改，而改动的方向本身就是一份关于 AI 原生工程的方法论清单——真正稀缺的不是会调 agent 的人，而是能在百万行代码库里做上下文工程、做架构判断、并且知道自己在验证什么的人。讲这门课的 Mihail Eric 说了一句最扎人的话：「大部分学生要被淘汰，少数会变得极其有价值。」

**讲者是谁：** Mihail Eric 是 Stanford 兼任教授，在 Stanford 开 CS146/146S「现代软件开发者」，同时是 Series B 创业公司 Monaco 的 AI 负责人——Monaco 做的是面向早期创业公司的全 AI 原生销售平台。他自己写的 agentic harness 就是课程第一周的教材：一个两百行左右的 agent 循环，只需要 CS106B 级别的算法基础就能写出来，但已经能读写文件、完成相当复杂的任务。这条路径的意义在于把「编码 agent 的神秘感」剥掉：剩下的那些是工程判断，不是魔法。

**课程十周的结构本身就是论点：** 第一周讲 harness 内部，从零写一个编码 agent；第二周讲规模化上下文工程与工具设计（MCP），他明确说自己「仍然支持 MCP」；第三周讲 skill——工具之外的过程化能力；第四周讲 agent 配置、hooks、sub-agents；第五周讲「agent-ready codebase」，这是他最喜欢的题目，讲一个仓库要怎样设计边界、文档与可验证性才能被 agent 有效消费；第六周讲 agentic code review——因为 code review 正在变成新的瓶颈；第七周讲安全，他的判断很直接：「今年我们见到大量东西被黑掉，包括 Vercel 到各种 LLM gateway 这类核心组件」；第八周讲后台 agent，参照的是 Ramp、Spotify、Stripe 这些公司公开的内部基础设施；第九周讲团队级基础设施（LLM gateway、MCP portal）与角色的演化；第十周讲软件工厂，以及人类还留在哪里——意图、可验证系统，以及「当 89% 的代码完全由 agent 驱动」时新的卡点在哪。

**最值得单独拎出来的一课是「把真实 harness 拆开看」：** 学生先写两百行版本，然后用 MITMProxy 拦截真实 Claude Code 的请求与响应，逐条看系统提示、规划提示、压缩提示分别长什么样。他注意到一个趋势：Claude Code 的系统提示曾经长达两万 token 左右、是同类产品里最长的，后来被砍掉了大约八成——因为原本写在提示里的东西（比如怎么用 Git、怎么设任务）现在被烤进了模型权重。他由此提出一个真问题：模型与 harness 之间的分工该往哪边投资。「我们作为社区一直在两者之间摇摆。」

**关于学习与教育：** 他花了整个夏天去谈开源合作方，把课程作业改成向真实的 AI 原生开源项目提交贡献——目的是让学生在大规模代码库里工作，并由 maintainer 亲自 review，「这样才有真正的优秀软件设计的传承」，顺便也成了招聘通道。他给学生的建议很具体：每天花十分钟，用新工具做一件你原本用旧方法做的事，「这样就能补上大部分差距」。他也没回避争议：「大多数学生是要被淘汰的」这句话他说完自己补了一句——这是个敏感话题，Stanford 的学生不用担心，但其他学校的学生怎么办，是个开放问题。

Direct quote: "Most students are cooked, some of them are gonna be super valuable."

> 这期的可迁移结论是：AI 原生工程的教学重心已经从「会不会用工具」移到了「会不会设计上下文与可验证性」，而这两件事恰好是自动化最难吞掉的部分。
