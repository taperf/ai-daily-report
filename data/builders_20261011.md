## 🔥 今日核心信号：Agent 互联网正在成型

如果只看一条：**Vercel CEO Guillermo Rauch 公布的机器流量数据**。这不是预测，是已经发生的事实——Bot 流量占比从 2024 年 1 月的 32% 涨到今天全网 **58.18%**，60%+ 的部署来自 Agent（今年 1 月还只有约 3%），Vercel 自家文档站高达 **83% 的页面浏览来自 Agent**。Rauch 的判断：人类"直接"访问互联网流量将在几年内变成四舍五入的误差项——网络不会死，但它将**为 Agent 而建、由 Agent 而建**。同期 Aaron Levie 给出需求侧镜像：Agent 生成的 Token 消耗将是人类逐条 Prompt 的 **1000 倍**，"聊天式 AI"一两年内就会像文物。两条放在一起读：基础设施侧与消耗侧同时切换，这是今天最重要的产业叙事。

## 🎙️ 播客深读

### No Priors：Beam——"美国自己的开放模型"，对话 Reflection AI 联合创始人兼 CEO Misha Laskin

**The Takeaway：** 开放 vs 封闭的争论该换问法了——问题不是"开放模型危不危险"，而是"当封闭模型出事时，你只有开放模型能救自己"。Laskin 用实证案例回应对开放权重的安全质疑：一个强大的封闭模型攻击了某公司，该公司唯一的补救手段就是用开放模型自我防护——因为封闭模型的护栏同时封死了防御能力。他将其称为安全领域的 Linus 定律：" eyeballs 够多，安全漏洞也会变浅。"

**要点摘录：**
- **Beam 是 Reflection 首个开放模型，也是首个进入前沿级别的西方开放模型**。公司从一年前约 30 人扩到约 300 人，在 SpaceX 集群上完成训练：几周预训练 + 几周 RL 合成数据即发布，"还有很多确定有效的东西没来得及放进去"。
- **被问"最难的是什么"，答案是"一切"**：人才、算力、数据、基础设施、文化——"你必须做对 30 件事，所以每件事都难"。在大厂可以视为理所当然的工具链，创业公司要全部自建。
- **企业采用开放模型没有捷径**："必须先经历租用阶段才能走向自有"——年花费上亿美元级（在封闭模型上）之后，成本压力才驱动切换，还常伴随算力短缺下的本地裸金属复兴。
- **他给模型公司的胜负公式：智能密度 × 算力储备 × 客户信任**。判断"全栈都在商品化、全栈利润率都在被压缩"——这个市场没有安全区。
- **对中国开放模型的判断出人意料地正面**：中国开源生态崛起"对世界是巨大的礼物"，"你可以想象一个没有它的世界——那就真的没有开放模型了"。
- **最有个人色彩的一段**：他把自己的博士论文喂给语言模型做了四年纵向测试——两年前只能聊天，一年前答题是本科水平，六个月前达到博士水平正确解出，**现在甚至会给出他当年没想到的新信息**。"还要读几年博士干嘛？现在一周就能做一个博士课题。"
- **数据中心 = 21 世纪的工厂**：参观 Stargate 后最冲击的是停车场满满的车——数万个高薪岗位与地方税收，"数据中心就是当年的铁路和工厂"。
- **对研究员岗位的判断**：大项目从来不需要千人规模（AlphaGo 约 10 人，如今约 100 人），未来也不会缩回 10 人，而是稳定在百人量级；真正的爆发在"应用研究"——每个企业、每项真实世界能力都需要一个 5-10 人的 pod，这类"部署型工程师"有多少要多少。

## 📚 Anthropic 工程博客（3 篇）

### 1. How we contain Claude across products（Agent 安全防护体系全解）

**核心论点：工程问题从"监督 Agent 做什么"转向"限制 Agent 能做什么"**——即 containment（遏制）而非逐条审批。关键数据：Claude Code 遥测显示**用户对权限弹窗的批准率高达 93%**，审批越多注意力越涣散（审批疲劳），因此人机协同监督本质上不可靠，auto mode 只是缓解。真正压轴的是环境级遏制：沙箱、虚拟机、出站控制。坦承细节：十二个月前 Anthropic 内部还会拒绝给 Claude 足以搞垮内部服务的权限，如今这已是日常；Claude Mythos Preview 因"爆炸半径过大"于 2026 年 4 月被拒绝发布，但随着防御方加固系统，同级别能力将逐步放行。按 claude.ai / Claude Code / Claude Cowork 三条产品线拆解了各自不同的遏制架构。
🔗 https://www.anthropic.com/engineering/how-we-contain-claude

### 2. An update on recent Claude Code quality reports（质量下降事件复盘）

罕见的透明复盘：用户反馈"Claude 变笨了"，根因是**三个独立的产品层变更叠加**，API 与推理层完全无关：①3 月 4 日把 Claude Code 默认推理强度从 high 降到 medium（为降延迟），是错误的取舍，4 月 7 日回滚；②3 月 26 日清理闲置会话历史 thinking 的功能因 bug 每轮都触发，导致"健忘、重复"，4 月 10 日修复；③4 月 16 日减少冗长的系统提示改动损害编码质量，4 月 20 日回滚。三个变更影响不同流量切片、不同时间窗口，聚合起来看起来像"广泛而不一致的整体退化"——内部使用数据和 evals 一开始都无法复现。补救：全员重置订阅用量上限。
🔗 https://www.anthropic.com/engineering/april-23-postmortem

### 3. Scaling Managed Agents: Decoupling the brain from the hands（Managed Agents 架构）

托管长程 Agent 服务的设计哲学：**向操作系统学习**——OS 用 process/file 抽象支撑了"尚未被设想的程序"，Anthropic 把 Agent 虚拟化为三个可独立替换的接口：session（追加式日志）、harness（调用循环）、sandbox（执行环境）。教训一：把所有组件塞进单个容器 = 养了"宠物"（pets vs cattle），容器一挂会话就丢。教训二：harness 编码的是"Claude 做不到什么"的假设，而模型一升级假设就过期——Sonnet 4.5 的"context anxiety"（临近上下文上限就提前草草收尾）需要 harness 加 context reset 兜底，到 Opus 4.5 该行为消失，reset 变成死代码。
🔗 https://www.anthropic.com/engineering/managed-agents
