## Aaron Levie — Box CEO

Box CEO Aaron Levie 给出了一套关于 agent 扩散速度的判断：模型在编码、工具调用、computer use、数学这些「编码类」任务上会持续变强，所以能用软件干活、或从零生成代码的 agent，进步速度会快过其他所有知识工作领域。这本来意味着能被自动化的只是工作的一小部分，但 Levie 认为更可能的结果是：越来越多工作会被改造成「编码形状」，去适配 agent 擅长的事。他举了近两个月模型发布的例子——agent 生成的代码可以变成动画视频、游戏、产品 3D 模型。他顺带修正了一个常见心智模型：过去大家以为模型必须什么都懂才能产生价值，实际上真正需要的是「高效使用或生成软件」加上「深厚领域知识」来做工作流里的判断，这个组合一旦成立，其余的东西几乎都会被解锁。

The contrarian bit is the direction of adaptation: instead of waiting for models to learn your domain, expect your domain to be restructured into code-shaped tasks.

> 反常识的地方在于适配的方向：不是等模型来学你的行业，而是你的行业会被改造成代码形状的任务。

## Guillermo Rauch — Vercel CEO

Vercel CEO Guillermo Rauch 展示了一个把 UI 当成 agent 原生接口的实验：两个 prompt、fx 加 Gemini Argon、纯 Web Components、不用框架，agent 直接复用了 14 个 UI SDK 行为——窗口缩放、拖拽、菜单栏悬停切换、typeahead、工具栏 roving focus、10 段均衡器滑块、作用域热键、ARIA，以及 WebMCP 的 agent 控制。他另一条讲自己的工作方式：所有项目都是「用最聪明的模型做规划，再委派给快模型 subagent 执行」，在 AGENTS.md 里只是一行指令，686 万字节的体积里塞下了完整的 subagent 能力。

The 14 reused behaviors are the actual point: once UI primitives expose themselves to WebMCP, an agent stops drawing screenshots and starts operating real components.

> 那 14 个被复用的行为才是重点：当 UI 原语向 WebMCP 暴露自己，agent 就不再是画截图，而是在操作真实的组件。

## Unsupervised Learning —《Ep 97: Jev Creator on Decision Models, Benchmark Fatigue & Why the Labs Missed It》

**The Takeaway：** 这家做「决策模型」的公司创始人给出的判断是：实验室真正被浪费掉的东西不是算力，而是早就存在的智能——「GPT-3.5 时代的模型在大量任务上已经超过中位数人类水平，可这一层智能从来没被拿去干活」。他更激进的说法是：现在大家疯狂追赶的「模型形状」其实不重要，重要的是可靠性；而整个行业正在用 benchmark 透支开发者的信任。

（说明：feed 提供的转写稿存在语音识别误差，播客名称与嘉宾姓名拼写不稳定，以下内容严格基于转写原文可确证的部分，涉及拼写的不做猜测性补全。）

这位嘉宾一个月前发布了一批「决策模型」（他在对话中称其为 system one 模型），理由是日常工作里绝大多数调用其实不需要人类可读的长文本。他的论证从一个问题开始：把 LLM 当成一个被软件调用的 API 子模块，那些调用里真正给人看的占多少、给计算机消费的占多少？他的经验是，即便是最「文本派」的人也会承认机器原生那一侧最终会占到绝大多数——「计算机并不想要字符串，它只在极端基数枚举这种很少见的场景才需要字符串，因为它处理的是比特」。所以他反推：从那个机器原生的「认知内核」往回设计。

关于为什么现在才做、以及行业为什么没做，他的答案很尖锐。他说自己在 OpenAI 时写过一份文档，标题是「我们本可以在一年前就有 AGI，至少按 OpenAI 的定义」——因为那个定义是「完成世界上大部分有经济价值的工作」，而 2023 年左右的模型在 GPQA 这类博士级难题上已经过了线。「那样的智能为什么没被投入使用？这很悲剧。」他由此推出一个更刺人的对比：为什么我们能解千禧年数学难题，却自动化不了任何涉及会计的工作？「这应该让很多人觉得非常奇怪。」

他对 benchmark 的敌意是这期最完整的一段论证。他担心的不是分数不准，而是「过度承诺、交付不足」在烧掉开发者的善意：没时间自己测的开发者会被榜单直接扫进去，而榜单恰恰测不出可靠性。「我觉得人们已经不再关心我们这一类模型的新发布，因为他们被忽悠太多次了。这对我们公司是好事，对整个领域是坏事。」他也不接受「用某个模型做某类任务」这种长期心智模型：那等于让系统锁死在某个供应商上，「智能的北极星应该像 SQL——可靠到与供应商无关」。

关于编码 agent，他给了一个具体的架构批评：几乎所有编码 agent 的交互设计都是围着 KV cache 转的，而 append-only 的状态让路由失效、让 subagent 变得低效（「你的状态就像一堆全局变量，一直传一个巨大的字典直到模型崩掉，然后它会越来越笨，因为 context rot 是真的」）。他想看到的东西很具体：多个 agent 真正共享同一份上下文、按任务语义重新压实状态、把旧会话历史做成一次极廉价的 MapReduce 而不是一个「模型觉得需要才调」的工具。他也承认这条路难：「不是这些想法有什么悲剧，悲剧是现在只有这一条路。」

数字方面他给了两个：编码 agent 对工程效率的提升，他的估计是 20% 到 40% 加速，且带上长期技能退化与技术债的误差棒；另外他说公司「可以盈利地运营这项服务」，融资的目的不是钱，而是把最有用的人拉到同一边。至于 Anthropic 的估值，他的回答是：「编码 agent 极有价值，但有多少实际使用是真正有价值的，不清楚——净为正和值不值这么多钱是两件事。」他还补了一句关于泡沫的判断：模型实验室最强的能力可能不是模型、产品或者分发，而是财务工程（尤其是在算力上的结构设计），「泡沫可以仅仅因为预期没兑现而破裂，不是因为技术不具变革性」。最后是那个被主持人称为好句子的比喻——关于「让他们治愈癌症」会是当代的「让他们吃蛋糕」。

> 这期真正可迁移的判断只有一句：可靠性和「任务形状」是两件事，而整个行业目前只在优化后者。
