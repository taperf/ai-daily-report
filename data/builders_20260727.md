### Anthropic Engineering: Claude Code 质量报告更新

Anthropic 发布了一份详细的技术复盘，回应了过去一个月用户报告的 Claude 响应质量下降问题。调查发现，三个独立变更影响了 Claude Code、Claude Agent SDK 和 Claude Cowork（API 未受影响），截至 4 月 20 日（v2.1.116）已全部修复：

1. **3月4日**：将 Claude Code 默认 reasoning effort 从高改为中，导致 Sonnet 4.6 和 Opus 4.6 的智能表现下降。4月7日已 revert。
2. **3月26日**：为降低闲置会话恢复时的延迟，添加了清除超过一小时未活跃会话旧思考内容的功能。但 bug 导致该操作在后续每轮对话中重复执行，使 Claude 显得健忘和重复。4月10日修复。影响 Sonnet 4.6 和 Opus 4.6。
3. **4月16日**：添加减少冗长度的系统 prompt 指令，与其他 prompt 变更组合后损害了代码质量。4月20日已 revert。影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

Anthropic 强调，由于每个变更在不同时间影响不同流量切片，aggregate effect 看起来像是广泛且不一致的质量退化。团队从 3 月初开始调查，但这些报告难以与正常用户反馈波动区分。这篇 postmortem 展示了 Anthropic 对质量问题的透明度和技术细节的重视。

### Anthropic Engineering: Scaling Managed Agents — 解耦大脑与双手

Anthropic Engineering Blog 发布了关于 Claude Managed Agents 的架构设计文章。核心思想是：为"尚未被想象到的程序"设计系统——正如操作系统通过虚拟化硬件创造了进程、文件等抽象，Managed Agents 虚拟化了 agent 的三个组件：session（追加式日志）、harness（调用 Claude 并路由 tool calls 的循环）和 sandbox（代码执行环境）。这使得每个组件的实现可以独立替换而不影响其他部分。

文章强调，harness 编码了关于 Claude "不能独自做什么"的假设，但这些假设会随着模型改进而失效。例如，之前发现 Claude Sonnet 4.5 会在感知到上下文限制临近时过早结束任务（"上下文焦虑"），于是他们在 harness 中添加了上下文重置。但当同一 harness 用于 Claude Opus 4.5 时，发现该行为已消失——重置变成了 dead weight。Managed Agents 的设计正是为了避免这种"假设过期"问题。

### Claude Blog: Managed Agents 新功能 — 自托管沙盒与 MCP 隧道

Claude 宣布 Managed Agents 的两项重要更新，均面向企业安全场景：

**自托管沙盒（public beta）**：agent 可在企业自己控制的基础设施中执行工具，或选择 Cloudflare、Daytona、Modal、Vercel 等托管提供商。敏感文件、代码、包和服务始终在企业边界内，agent 的编排、上下文管理和错误恢复仍由 Anthropic 基础设施处理，但工具执行移至企业配置的环境。

**MCP 隧道（research preview）**：Managed Agents 可连接至企业私有的 MCP 服务器，使 agent 能安全访问内部 API、数据库和工具。申请访问权限即可试用。

这两项功能解决了企业部署 AI agent 时的核心顾虑：数据不出境、执行环境可控、与现有安全基础设施兼容。

### Unsupervised Learning Ep 91: 顶级 AI 分析师拆解当前炒作周期

**嘉宾**：Benedict Evans（独立科技分析师，前 a16z 合伙人）
**主持人**：Jacob Efron（Redpoint 投资人）
**收听**：https://www.youtube.com/watch?v=vDY_ocrkQ5w

Benedict Evans 是科技行业最受尊敬的战略思考者之一，本期节目中他与 Jacob Efron 深入探讨了 AI 生态系统的多个核心命题。

**核心观点摘要：**

**AI 是多大的事？** Evans 认为将 AI 与互联网、移动、PC 比较是合理的——它们都曾改变世界。但他反对"史无前例"的叙事："人们在没有电之前也不傻。"他建议回顾历史上每一次平台变革的模式，而非争论哪个更大。移动网络花了 15 年将流量提升 1000-2000 倍，年资本支出 2000 亿美元，但大部分价值被上层应用（Uber、YouTube）捕获，运营商本身并未获得。

**基础模型的价值归属：** Evans 对基础模型能否捕获生态系统的绝大部分价值持怀疑态度。他以 TSMC 为例：净利润是苹果的一半，是非常棒的公司，但 Uber 不会给 TSMC 写支票。技术栈的每一层都有不同的价值捕获方式。基础模型可能像半导体一样，成为被整合到操作系统中的 enabling layer——正如打印功能从独立 DOS 应用变为 OS 内置功能。OpenAI 和 Anthropic 没有基础设施、没有分发渠道，有的只是前沿科学，"他们必须在 commodity foundation model 之上找到可构建的东西"。

**消费者 AI 为何不 work：** Evans 认为当前 chatbot 的困境类似于 90 年代中期的互联网——"它很酷，但它不 work"。他回忆起 1999 年用 Palm V 通过红外连接 Nokia GPRS 手机上网的体验："天哪这太酷了"——但其实并不 work。正常用户不是 1992 年用 Telnet 上网的那批人。更根本的问题在于，AI 有边际成本——这是与以往所有平台 shifts 的关键区别。你无法先做一个消费者应用获取 1 亿用户再想办法变现，"这就是为什么现在全是企业而非消费者"。

**chatbot 是不是 web browser？** Evans 对这个问题持矛盾态度。他记得 90 年代末的互联网门户——不能给用户一个空白地址栏的浏览器，必须帮他们。现在 chatbot 界面里的小方块（"你可以做这个、可以做那个"）是不是就是当年的门户？他不知道答案。关键在于：多少 LLM 使用是你已经在做的事（搜索、订机票），多少是创业者才能发明的全新行为（Flickr → Instagram → TikTok）。

**企业 AI 部署的现实：** Evans 认为企业 AI 的真正挑战不是技术，而是组织。"第一步是给每个人一个 copilot。第二步：哎呀。第三步：我们做点别的。"他 joking 说"如果你说 digital transformation 三遍，一个 Accenture 合伙人就会在一阵烟雾中出现"——但这也说明，重构企业流程是一个巨大的咨询项目，"没有公司会坐着一群闲着没事干、等着重新想象一切的人"。他特别指出，垂直企业软件公司和咨询公司在做同一件事——"你这样做，但你可以那样做，效果会更好"——只是从相反方向爬山。

**OpenAI 的新 app 策略：** Evans 认为 OpenAI 去年下半年的策略转变是"在 commodity foundation model 之上能构建什么？是浏览器吗？是广告吗？是一切？"如果走慈善路线，钱更少、更聚焦、更担心邪恶——fine。如果 stumble into coding 是可行的路径，那就走这条路。但他对 OpenAI 近期的 app 发布评价不高："如果这告诉你一件事，那就是他们在写连他们自己都不信的备忘录。"

**对 lab 领导人谈论失业的看法：** Evans 认为这"深入逻辑谬误"。Jeff Hinton 十年前说"别再培养放射科医生了"——但问题是他并不真正了解放射科医生做什么。更广泛的类比是：互联网根本没有改变"记者是什么"，但它摧毁了本地广告业务——这完全不在你的分析框架内。Uber 同理：没人会看着智能手机想到"我要摧毁出租车行业"。AI 的影响将出现在你意想不到的地方。

**AGI 概率分布：** Evans 用了一个精妙的类比——古巴导弹危机时股市恐慌，一位老交易员出去买入，理由是"这是二元的：要么是真的（那我们反正都死了），要么不是（那股票就很便宜）"。如果 AGI/ASI 真的发生，"我们有比中产失业更大的问题"。否则，"让我们专注于弄清楚这对企业软件意味着什么"。

**最有力的反驳：** Evans 承认，AI 与以往平台 shift 的真正区别在于"我们不知道它的物理极限"。2010 年你不知道下一款 iPhone 是什么，但你知道它不会有视网膜植入、一年续航和飞行能力。AI 的能力边界是未知的，这使得长期预测尤为困难。
