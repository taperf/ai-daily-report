## Aaron Levie — Box CEO

Box CEO Aaron Levie 给出了一套关于 agent 扩散路径的判断：模型在编码、工具调用、computer use、数学等「编码类」任务上会持续变强，所以能用软件干活、或从零生成代码的 agent，进步速度会快过其他所有知识工作领域。这本来意味着能被自动化的只是工作的一小部分，但 Levie 认为更可能的结果是：越来越多工作会被改造成「编码形状」，去适配 agent 擅长的事。他举了近两个月模型发布的例子——agent 生成的代码可以变成动画视频、游戏、产品 3D 模型。他还修正了一个常见的心智模型：过去大家以为模型必须什么都懂才能产生价值，实际上真正需要的是「高效使用或生成软件」加上「深厚领域知识」来做工作流里的判断；这个组合一旦成立，其余的东西几乎都会被解锁。

The contrarian bit is the direction of adaptation: instead of waiting for models to learn your domain, expect your domain to be restructured into code-shaped tasks.

> 反常识之处在于适配的方向：不是等模型来学你的行业，而是你的行业会被改造成代码形状的任务。

## Unsupervised Learning —《Ep 97: Jev Creator on Decision Models, Benchmark Fatigue & Why the Labs Missed It》

视频链接：https://www.youtube.com/@RedpointAI

> 说明：feed 提供的转写稿存在语音识别误差，播客标题本身是准确的，但嘉宾姓名与公司名在转写里拼写不稳定，以下内容严格基于转写原文可确证的部分，不对拼写做猜测性补全。

**The Takeaway：** 这位做「决策模型」的创业者给出的判断是：真正被浪费掉的不是算力，而是早就存在的智能——「GPT-3.5 时代的模型在大量任务上已经超过中位数人类水平，可这一层智能从来没被拿去干活」；而整个行业正在用 benchmark 透支开发者的信任，这才是当下最贵的一笔账。

**为什么会信这门生意：** 他的论证从一个问题开始。把 LLM 当成一个被软件调用的 API 子模块，那些调用里真正给人看的占多少、给计算机消费的占多少？他的经验是，即便是最「文本派」的人也会承认机器原生那一侧最终会占到绝大多数——「计算机并不真的想要字符串，它只在极端基数枚举这种很少见的场景才需要字符串，因为它处理的是比特」。所以他反推：从那个机器原生的「认知内核」往回设计。他公开说 model 现在还没到那一步，还有大量工作要做，这是他每天的动力。

**为什么行业没做：** 他的答案很尖锐。他说自己在 OpenAI 时写过一份文档，标题是「我们本可以在一年前就有 AGI，至少按 OpenAI 的定义」——因为那个定义是「完成世界上大部分有经济价值的工作」，而 2023 年左右的模型在 GPQA 这类博士级难题上已经过了线。「那样的智能为什么没被投入使用？这很悲剧。」他由此推出一个更刺人的对比：为什么我们能解千禧年数学难题，却自动化不了任何涉及会计的工作？「这应该让很多人觉得非常奇怪。」

**对 benchmark 的敌意是这期最完整的论证：** 他担心的不是分数不准，而是「过度承诺、交付不足」在烧掉开发者的善意——没时间自己测的开发者会被榜单直接扫进去，而榜单恰恰测不出可靠性。「我觉得人们已经不再关心我们这一类模型的新发布，因为他们被忽悠太多次了。这对我们公司是好事，对整个领域是坏事。」他也不接受「用某个模型做某类任务」这种长期心智模型：那等于让系统锁死在某个供应商上，「智能的北极星应该像 SQL——可靠到与供应商无关」。他甚至说，自己对更新依赖这件事的厌恶，比追求最新模型更接近真实的工程直觉。

**对编码 agent 的架构批评相当具体：** 几乎所有编码 agent 的交互设计都是围着 KV cache 转的，而 append-only 的状态让路由失效、让 subagent 变得低效——「你的状态就像一堆全局变量，一直传一个巨大的字典直到模型崩掉，然后它会越来越笨，因为 context rot 是真的」。他想看到的东西也很具体：多个 agent 真正共享同一份上下文、按任务语义重新压实状态、把旧会话历史做成一次极廉价的 MapReduce 而不是一个「模型觉得需要才调」的工具。他也承认这条路难：「不是这些想法有什么悲剧，悲剧是现在只有这一条路。」

**几个关键数字与判断：** 编码 agent 对工程效率的提升，他给的估计是 **20% 到 40% 加速**，并且明说误差棒很大，长期还有技能退化与技术债的代价；公司「可以盈利地运营这项服务」，融资不是为了钱，而是把最有用的人拉到同一边；关于 Anthropic 的估值——「编码 agent 极有价值，但有多少实际使用是真正有价值的，不清楚。净为正和值不值这么多钱是两件事。」关于泡沫：「实验室最强的能力可能不是模型、产品或者分发，而是财务工程（尤其是算力上的结构设计）。泡沫可以仅仅因为预期没兑现而破裂，不是因为技术不具变革性。」

Direct quote: "There's so much more to do. It's a sad state of the world — it's very counter to how software engineering tends to work."

> 这期真正可迁移的判断只有一句：可靠性和「任务形状」是两件事，而整个行业目前只在优化后者。
